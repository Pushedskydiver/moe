**Novel patterns this session:**

1. **A cited precedent can be real and still only half-copied.** `createGithubIssue`'s claim-first guard genuinely does distinguish definitive from ambiguous failure — the citation itself was accurate — but the new code only implemented the ambiguous-failure half, and DA caught the gap by reading the cited file directly rather than trusting the paraphrase in the code comment that cited it.
2. **Self-verification via real mutation testing is a legitimate substitute for another review round when the reviewer already prescribed the exact fix** — used twice this session (a wording fix on 3.8, R2's own null-input test gap on 5.2b), each time by reverting the fix, confirming the test's own pre-fix behavior, and restoring. 3. **A helper-function extraction done purely to satisfy `max-lines-per-function` can silently detach a doc comment from the function it describes**, if the extraction inserts a new function between the comment and its target. Caught by `copilot-surrogate` in one file, then proactively found and fixed in a second file with the identical shape (as plain `//` comments, so not technically JSDoc-misattached, but equally misleading to a human reader) — worth checking for on every future extraction of this kind.
4. **A test's title making an ordering claim its own assertions don't check is a real, if quieter, defect than a title describing the wrong scenario entirely** — both showed up in this session's review (the confirming-question DM test had the wrong scenario; its High-band sibling had the right scenario but an unverified claim in its own title), and both were worth fixing, not just the more obviously "broken" one.
