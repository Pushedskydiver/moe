**Major novel patterns this session:**

1. **A false-pass regex assertion can survive multiple real, independent fix rounds before the actual root cause surfaces** — five consecutive rounds each found something genuinely real and narrower (not noise, not the same bug recurring), and per-instance patching (fixing the specific phrase/keyword each round flagged) kept reopening the same _shape_ of gap on a sibling case in the same expression. 4. **Making a documented claim true by fixing the code, rather than softening the claim to match the code, is usually the better fold** when the gap is cheap to close (this session's re-record-command-naming fix) — but the reverse (narrowing an overclaim's own text) is still correct when the described behavior itself needs redesigning, not just gap-filling (the fixture-shape claim).
