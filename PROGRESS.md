1. **Fixing a review finding can uncover — or itself introduce — the next gap in the same call chain, repeatedly.** Three consecutive rounds (R1→R2→R3) each found the previous commit's fix only partially closed the underlying "malformed/adversarial `DATABASE_URL` crashes or leaks" class, via a different specific code path each time (a bare `new URL()`, then `decodeURIComponent`, then an un-escaped control character in the generated env file).
