**Two real defects surfaced that the chunk's own filed scope never anticipated**, both found during planning rather than after shipping: (1) a **cost-accounting gap** — the SDK returns cache spend on `cache_creation_input_tokens`/`cache_read_input_tokens`, separate from `input_tokens`, so wiring `cache_control` without widening the usage types and `sonnetCostUsdMicros` would have made persona-prompt tokens (the majority of every call's input, and the entire point of caching) silently vanish from the monthly cost cap; fixed in the same PR that added the first `cache_control`; (2) a **build/deploy gap** — `packages/agents` builds with plain `tsc`, which never copies `.md` into `dist/`, so `prompt.md` only reached the deployed image because the root `Dockerfile` happens to `COPY` all of `packages/`, contradicting that package's own `"files": ["dist"]`; a future Dockerfile slimming would have broken persona loading in production with no test or CI signal. Fixed by copying `src/personas` into `dist/personas` at build time, with a `dist/`-importing integration test as the CI-visible tripwire (verified to actually fail when the copy step is removed).

**The session's sharpest lesson was a misdiagnosis that three independent review passes shared.** DA review found the new confirming-question call site broke the model's structured output near-100% of the time on a message combining a quote character with classifier-field-label-shaped text. DA, its own fresh-context R2, and Claude each independently confirmed the _symptom_ and its failure rate — R2 twice re-ran its own live tests rather than trusting any narrative, and correctly refused to rubber-stamp an overclaiming comment — yet all three converged on the same wrong _cause_ (JSON escaping / delimiter spoofing), concluded it was unfixable by prompt construction, and shipped it as a documented accepted risk in the PR description. **Alex asked whether it was worth fixing.** Testing four alternative constructions (two of which made it _worse_) forced capturing `stop_reason`/`output_tokens`, which answered it in one call: **`MAX_TOKENS` truncation**. Adversarial input provokes heavy extended thinking, thinking counts against `max_tokens`, and at 256 the whole budget went to a `thinking` block with no JSON emitted at all — one legitimate run needed 1126 tokens. Raising the ceiling fixed it completely (12/12 across four input shapes, driven through the real exported function from built `dist/`). Sibling exposure was live-checked rather than assumed: `composeTicketDraft`'s 512 sits comfortably clear, so this is a per-task ceiling, not a repo-wide constant. Two durable lessons, both recorded at the call site: `stop_reason`/`output_tokens` distinguish truncation from malformed output immediately, so check them before theorising about escaping; and **adversarial-robustness testing that only ever asserts "it failed safely" can confirm a symptom indefinitely without ever finding its cause** — every round here verified the fallback held, which is exactly why nobody looked further.

**Methodology carried forward from Session 27 and extended:** live adversarial validation against the real model (never simulated) ran on every PR that touched persona-prompt-adjacent behaviour — ~35 real messages across four rounds this session, including two rounds run by review agents independently re-testing rather than trusting a commit's own account. That independence is what caught an overclaiming comment; it is _not_ what caught the root cause, which needed a different diagnostic entirely.
