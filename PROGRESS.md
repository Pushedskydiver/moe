**Major novel patterns this session:**

1. **A false-pass regex assertion can survive multiple real, independent fix rounds before the actual root cause surfaces** — five consecutive rounds each found something genuinely real and narrower (not noise, not the same bug recurring), and per-instance patching (fixing the specific phrase/keyword each round flagged) kept reopening the same _shape_ of gap on a sibling case in the same expression. The fix that actually held was structural: identify what the two real transcripts actually differ on (does the reply _open_ with a plan or a stall) rather than continuing to enumerate phrases that shouldn't appear anywhere in the text.
2. **A design doc's own prediction about a build-script consequence ("harmless redundant copy") can be wrong until the build is actually run.** `cp -r`'s destination-exists nesting behavior wasn't caught by the two-phase spec-grill (which reasoned about the change correctly in every other respect) — only by running `pnpm build` and reading a pre-existing regression test's own failure.
3. **A batch/recording script reusing a production client builder can need a different tuning value than every existing call site**, even when the builder itself is correct and well-factored — the fix is a per-caller override with an unchanged default, not a blanket increase or a hand-rolled second client.
4. **Making a documented claim true by fixing the code, rather than softening the claim to match the code, is usually the better fold** when the gap is cheap to close (this session's re-record-command-naming fix) — but the reverse (narrowing an overclaim's own text) is still correct when the described behavior itself needs redesigning, not just gap-filling (the fixture-shape claim).

Two durable lessons, both recorded at the call site: `stop_reason`/`output_tokens` distinguish truncation from malformed output immediately, so check them before theorising about escaping; and **adversarial-robustness testing that only ever asserts "it failed safely" can confirm a symptom indefinitely without ever finding its cause** — every round here verified the fallback held, which is exactly why nobody looked further.

**Methodology carried forward from Session 27 and extended:** live adversarial validation against the real model (never simulated) ran on every PR that touched persona-prompt-adjacent behaviour — ~35 real messages across four rounds this session, including two rounds run by review agents independently re-testing rather than trusting a commit's own account.
